# Meridian / Callosum — Working Rules

The rules of the road for anyone (human or agent) working in this repo. Authoritative detail lives in the linked docs; this page is the short, enforceable summary. When a rule here and a linked doc disagree, the linked doc wins.

Related: [PRD.md](./PRD.md) · [ROADMAP.md](./ROADMAP.md) · [AGENTS.md](./AGENTS.md) · [CONTRIBUTING.md](./CONTRIBUTING.md) · [docs/architecture.md](./docs/architecture.md) · [docs/ARCHITECTURE_DECISIONS.md](./docs/ARCHITECTURE_DECISIONS.md) · [frontend/DESIGN.md](./frontend/DESIGN.md) · [frontend/PRODUCT.md](./frontend/PRODUCT.md)

## 1. The frozen core is sacred

- The verified retrieval/extraction core (ingest, extract, retrieve, store, schema) is **frozen** at tag `eval-baseline-v3`. Do not edit it to add product features.
- The only sanctioned exceptions are tenancy predicates that *remove* rows (never add), applied brick-by-brick with a failing test first. See [CONTRIBUTING.md](./CONTRIBUTING.md) for the frozen-file list.
- Every change is verified against the frozen eval baseline (mechanism gate: candidate recall, gold-seeded 2-hop traversal, RBAC) before it ships.

## 2. Provenance and permission are non-negotiable

- No AI output mutates institutional memory until an authorized human approves it.
- Every surfaced graph fact carries a machine-checked verbatim source quote. Never show a summary without its evidence.
- Access control excludes confidential content **before** retrieval. Withheld sources are disclosed as a count only — never their content, title, or existence beyond that count.

## 3. Multi-tenancy is fail-closed

- Postgres: RLS `ENABLE` + `FORCE`; runtime connects as the non-superuser `callosum_app` role and sets `app.workspace_id`.
- Neo4j (no RLS): `workspace_id` is baked into entity MERGE identity and every read is scoped. All new/modified Neo4j access goes through the query gateway (`src/callosum/graph.py`); raw `session()` outside the gateway/allowlist is banned by test.

Eight backend PRs merged between 2026-08-09 and 2026-08-11. That falsifies the estimate — it does not excuse how they landed, and the two are recorded separately here on purpose. **What changes:** backend feature development is open again under Devguru's ownership (§5), and ROADMAP phase order becomes advisory rather than blocking — a phase may begin before the previous one's exit gate is claimed, provided the accepted-count in `ROADMAP.md` is not advanced by it. The product track stands at 3/13 accepted and only an exit gate moves that number. **What does not change, and was never what the freeze was protecting:** §1 — the frozen core, where a tenancy predicate may still only *remove* rows, applied brick-by-brick with a failing test first and the mechanism gate run *before* the change ships, not after; §2 — evidence, provenance and the append-only audit trail, which no feature may record an event into that did not happen; §5 — the frontend belongs to the maintainer; and review before merge, which "commit and push only when the owner asks" already covered and which self-merging one's own pull request does not satisfy. **Permission to build is not permission to self-approve.** That sentence is the governance change this amendment exists to make: the freeze was never what stopped bad work reaching master — review was, and there wasn't any. Eight pull requests merged between 2026-08-09 and 2026-08-11 carried zero reviews between them, and what rode in included a widening of the fail-closed RBAC gate, a notification dispatcher that recorded deliveries it never made, and three migrations whose revision IDs were too long for Alembic to apply. Reopening feature work without restoring review would reproduce that outcome faster, not prevent it. Recorded here rather than left to lapse: a rule that stops being enforced without being amended is worse than either keeping it or dropping it. **How a deferral is reopened:** #62, #93 and #100 may be reopened. A deferral is reopened by **reopening the issue and meeting the acceptance criteria it recorded** — never by closing it with work that does not address them. #93 was closed by a voting policy engine that is not CP-F, CP-G or CP-H; #100 was closed by a 79-line test file while the live graph endpoint, the server-side withheld-count contract and the layout strategy all remain undone. Both now read as resolved while their criteria are unmet. That is the failure the original sentence was guarding against, and it survives this amendment intact.
- **One verified change per commit.** Smallest change that increases confidence. No drive-by refactors, no churn.
- Branch off the default branch; never commit straight to it. **Commit and push only when the owner asks.**
- Fix only real, reproduced bugs. Measure before refactoring — let the problem pick the work.
- Release cadence = merge → freeze → tag → graphify snapshot → publish notes → postmortem. A release is an immutable, self-contained bundle.

## 6. Frontend design rules

Full system in [frontend/DESIGN.md](./frontend/DESIGN.md). The short version:

- **Semantic tokens only.** Components reference roles (`accent`, `surface-raised`, `muted-foreground`, `memory-emphasis`) — never a raw hex or a palette step (`blue-600`, `slate-100`).
- **Color communicates meaning (95% neutral / 5% semantic):** Blue = action · Green = success · Amber = pending/attention · Red = critical · **Violet = Institutional Memory only** (never a button or nav). No neon, no glow-as-default.
- **Gradients, owner's decision 2026-08-13 — permitted, registered, and measured.** The previous rule read "no gradients"; it is amended rather than dropped, because the dashboard it produced was uniformly flat and the fix the owner chose is a focal surface with depth. **Two constraints make this a design decision instead of a licence.** First, a gradient is **anchored to a semantic family, not free**: the operational hero ramps ink→blue-ink because it carries the primary action, the institutional-memory panel ramps ink→violet-ink. The colour vocabulary that §6 exists to protect is unchanged — violet still never means "button". Second, **at most two gradient surfaces per page**, both deep-ink based, and never on buttons, badges, chips, charts, icons, small panels or text. A third gradient is not a stylistic excess; it is the point at which the page stops having a focal surface at all. **The AA floor is not relaxed — it is sampled differently.** Text on a gradient sits on a *range*, so contrast is verified at the ramp's **lightest point in light theme and its darkest in dark**, never its midpoint, which always flatters a gradient. Every gradient in `globals.css` must be declared in `frontend/__tests__/palette-contrast.test.ts` stating whether text sits on it; an undeclared one fails the suite. That test is what makes this amendment enforceable rather than aspirational, and it did not exist before this date — the palette's published figures had been generated, documented and then left unguarded.
- **Elevation, not color, reduces flatness.** Four levels: (1) normal white cards — subtle border + tiny shadow; (2) important cards (Meeting Hero, AI panel) — stronger elevation; (3) floating UI (dialogs, dropdowns, command palette) — blur; (4) **the focal surface, owner's decision 2026-08-13** — one deep-ink card per page, permitted to carry a gradient per the rule above, holding the single most important thing on the screen. Level 4 is a *count*, not a style: two of them is none of them. Blur/transparency is reserved for the header, AI sidebar, and floating UI; content cards stay solid for readability.
- **Light-first, with a dark theme as of 2026-08-09.** Light is the tuned palette and the one reviews judge; dark is generated the same way, not inverted, and held to the same AA floor. It is delivered by re-pointing semantic tokens only — a component that needs a `dark:` class to look right is a component that named a colour it should not have. Cards 16px radius, controls 12px, badges fully rounded.
- **WCAG 2.2 AA is a hard floor.** Body text ≥4.5:1 (large ≥3:1), visible non-color-only focus rings, full keyboard paths, `prefers-reduced-motion` alternatives.
- Voice is plain and calm — no sci-fi theatrics.
