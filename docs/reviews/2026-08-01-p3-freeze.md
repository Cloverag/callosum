# P3 freeze record — authenticated API and application shell

**Date:** 2026-08-01 · **Master at freeze:** `caf650d` · **Migration head:** `0017_principal_identity`
**Research baseline:** `eval-baseline-v3` — unchanged and unaffected

This is a **freeze**, not an exit-gate pass, and the distinction is the point of this
document. P3 is feature-complete through CP-E. It does **not** claim its exit gate,
because two of its three stated exit criteria were deliberately deferred (#93) and
declaring the phase "accepted" would be the kind of paper progress the ROADMAP's
operating rule exists to prevent.

## Why the phase is being frozen rather than finished

The project's goal changed on 2026-08-01: from an open-ended product roadmap to a
portfolio-ready artifact by **November**. At part-time hours that is roughly 13 weeks,
against ten remaining phases. Continuing to add features has lower value than making
what exists legible, so feature work stops here and the remaining runway goes to the
technical writeup, the README, the demo and deployment.

CP-F, CP-G and CP-H stay deferred. They are recorded roadmap items with an owner and a
due phase, not unfinished work quietly left out.

## P3 exit criteria, honestly scored

ROADMAP states three:

> users access only authorized workspaces; UI distinguishes draft/approved/withheld/
> failed states; primary flows pass keyboard and accessibility smoke checks.

| Criterion | Result | Evidence |
|---|---|---|
| Users access only authorized workspaces | **MET** | OIDC + `principal_identity`; workspace re-validated per request; clearance resolved from `membership` on every call; OpenAPI guard fails the build if any endpoint declares `workspace_id` or `clearance`; cross-workspace negative tests on every aggregate |
| UI distinguishes draft / approved / withheld / failed | **PARTIAL** | draft/approved/withheld are distinguished and tested — the withheld discipline survives the write path (`test_a_write_response_is_clearance_filtered`). **Failed and loading states are CP-F, deferred.** Five surfaces handle errors explicitly; there is no systematic treatment |
| Keyboard and accessibility smoke checks | **NOT MET** | CP-G, deferred to P9 (#93). The design system was built to WCAG 2.2 AA and `rules.md` §6 holds it as a hard floor — but **deferring CP-G defers the verification, not the standard.** Any accessibility claim in the writeup must say "designed to AA, not audited" |

**One of three met, one partial, one not met.** P3 is therefore frozen as
feature-complete, and the product track stands at **3 of 13 phases accepted**, unchanged
from P2. Counting P3 as accepted would make the roadmap say something the evidence does
not support.

## Findings this phase, and what each cost

Every mock swap was supposed to be a change of transport. Six of seven found a defect
instead:

1. `include_inactive` — invented *and* lossy, collapsing a tri-state
2. three phantom `Meeting` fields — `agenda`, `objectives`, `sensitivity`
3. a nullable scheduling window declared as required
4. `clearance` accepted as a *client* argument on packs
5. `board_member_id` declared in TypeScript and dropped by `_row_to_stance`
6. **the packs page joining real ids against a mock** — every item in every pack
   rendered "Document reference could not be resolved"

And one that was not a swap at all:

7. **every "approved fact" on the dashboard was fabricated.** Five quotes, none in
   `data/demo/`; two named sources were not documents. Rendered under the heading
   "Evidence, not summaries — each with its source quote", which breaks the single
   claim the system exists to make (`rules.md` §2)

`commitments` was the one clean swap, and the reason generalises: it is the only mock
written **after** its domain shipped. Every defect above came from a mock authored
before the Python existed. Write the domain first and the swap is transport; write the
mock first and it is a negotiation.

## Limitations carried into the freeze

Stated here so the writeup does not have to rediscover them:

1. **The corpus is entirely synthetic.** 16 authored files about a fictional company.
   `docs/findings.md:481` names this as the honest next step and it has not been taken.
   The `locate()` CRLF bug found in #90 is the proof it matters: a defect that would
   silently drop edges from every Windows-sourced document survived 461 tests and a
   green gate, because no file in `data/demo/` uses CRLF.
2. **`app.workspace_id` is an ordinary GUC.** RLS guards application bugs, not a
   compromised database role.
3. **Composite-FK protection covers 1 relationship of 10** (#41).
4. **Accessibility is designed, not verified** (CP-G deferred).
5. **`graph` and `assistant` are snapshots, not live reads** (#100). Both show real
   data; neither is wired to the engine.
6. **No CI.** Every verification in this document is a local run.

## What may still change after the freeze

Critical bug fixes, documentation, demo polish, deployment, and evaluation reporting.
Nothing else. CP-F/G/H are not to be reopened because time remains — they are the
record of a scope decision, and reopening them would undo the only thing that makes a
deferral honest.
